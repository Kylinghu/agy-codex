## 1. 交付变更总览

### 新增模块

- [`skills/agy-codex/scripts/runtime.py`](../skills/agy-codex/scripts/runtime.py)：共享执行内核（纯 Python 标准库）
  - 抽取原 `controller.py` 的公共底座：`WorkflowError`、`Interrupted`、`now`、`encode`、`_metadata_io`、`atomic_json`、`read_json`、`git`、`resolve_codex`、`pid_alive`、`stop_process`、`launch_gate`、`WindowsJob`、`worktree_lock`、`EventSummary`、`codex_settings`、`configured_codex`、`codex_exec_flags`、`run_process` 与 `_child-gate` 入口。
  - **统一工作区解析（Git 与非 Git）**：Git 仓库复用 `<gitdir>/superagent/` 与原 `worktree.lock`；非 Git 目录状态按 `os.path.normcase(resolve(cwd))` 哈希至 `AGY_CODEX_STATE_DIR`（默认 `~/.gemini/config/agy-codex/workspaces/<hash16>/`），不污染用户交付目录，不执行 `git init`。
  - **稳定互斥域与原子单写入租约（`acquire_writer_lease`）**：非 Git 工作区锁与全局短登记锁 `registry.lock` 固定在独立于 `AGY_CODEX_STATE_DIR` 的稳定用户互斥域 `_mutex_base()` 下，避免以不同状态根规避互斥；在短登记锁临界区内原子完成“路径分量祖先/后代重叠检查 → 获取工作区锁 → 核查活跃 Strict Ticket 及含未发布 manifest 的 Strict Plan 占用 → 登记所有权”，执行期间释放登记锁；`sandbox="read-only"` 不占用写锁。
  - **单一执行与恢复内核（`execute_run` / `reconcile_run`）**：以 `Run`（`runs/<run_id>/run.json`，含纳秒级 `started_ns` 排序）作为唯一运行事实来源；`resolve_resume` 支持 `RUN_ID` / 原生 `THREAD_ID` / 工作区 `last`，禁止跳过未对账后继 Run，保留同主机/`CODEX_HOME`/Provider 约束；外部未登记 Thread ID 在未完成原生 `cwd` 核验前不写入本地归属，且禁止在 `exec` 或未核验回退路径中盲目续跑；`reconcile_run` 同时核验原主机与原 `CODEX_HOME`。

## 2. 本机 `developerInstructions` 最小实测结论

针对 Round 4/5 约定的 `ThreadStartParams.developerInstructions` 语义，在 `codex-cli 0.171.0` 上执行了两次对照探针并直接检查 Codex 持久化 rollout 文件：

1. **与原生基础指令及 `AGENTS.md` 共存**：传入 `developerInstructions` 时，rollout 中 `ORD 3`（17,793 字符 Codex 原生 base developer 指令）、`ORD 4[1..6]`（Memory/Skills/Permissions/Collaboration Mode/Tools）及 `ORD 5`（全局 `~/.codex/AGENTS.md` 与项目 `AGENTS.md`）均完整保留；`thread/resume` 后续回合继续生效且无需重发。
2. **与用户自定义 `config.toml` `developer_instructions` 冲突（关键实测）**：在 `codex app-server -c 'developer_instructions="USER_CFG_MARKER"'` 下同时通过 `thread/start` 传入 `developerInstructions="PLUGIN_MARKER"`，检查完整 rollout 文件结果：`HAS_USER_CFG_MARKER: False`、`HAS_PLUGIN_MARKER: True`。
3. **决策**：`ThreadStartParams.developerInstructions` 会**覆盖**用户 `$CODEX_HOME/config.toml` 中自定义的 `developer_instructions` 槽位。按 Round 5 §1 约定，**不采用原生 `developerInstructions` 注入**，继续沿用 `SKILL.md` 新任务委派传递，确保零覆盖风险与 App Server / Exec 语义一致。
